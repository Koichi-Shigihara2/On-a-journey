## 2. 2026Q3 の遅れ（82銘柄）

集計の方法: 各銘柄の `company_facts.json` から、2026-10-01 以降に提出された最新の 10-Q/10-K（accn）を取り、(a) Layer3 に入った日＝その accn が初めて `company_facts.json` に現れた bot の commit、(b) TANUKI の出力に出た日＝`latest.json` の `fcf_ttm_end` がその期末になった最初の commit、で測った。決算の発表日は **Yahoo の予定日**（`common/market_data/attributes/{T}.json` の `calendar.earnings_date` の履歴。8-K の実際の発表日ではない。誤差1〜2日）。日付は JST。

**82銘柄の内訳**: 64銘柄は 10-01 以降に10-Q/10-Kを提出済み／18銘柄は未提出。
- 提出済み64のうち TANUKI の出力まで測れたのは62（CRWV は TTM が5四半期そろわず `fcf_ttm_end` が無い、RCAT は 11-16 提出で Layer3 に入ったのが 11-23 03:49 だが、TANUKI は最新期の営業CFが未取得で年次の値を代用しており（`latest_period_missing`）`fcf_ttm_end` が無い。ここでは除外）。
- 未提出の内訳: 次の決算がこれから（ADSK・DELL は 11-25 発表、AVAV・CRM・GTLB・IOT・MRVL・RBRK・S・SNPS・HEI・HQY は12月）／**発表済みで未提出・未反映: NVDA（11-18）・AMAT（11-13、10-K は12月上旬が通例）・WMT（11-19、10-Q は12月上旬が通例）・CEG（提出済みで SEC_LAG）**。
- ADBE・CPRT は 9月の提出（決算期がずれている）で10月以降の提出が無いため、Q3の集計から外した。

## 3. 案（決めてほしいことを付ける）

### 案A: 平日に新しい提出を検知して、その銘柄だけ取って連鎖を回す

- **検知の道具はもうある**: `SEC_Data_Update` は毎回 submissions を全銘柄で取って「手元に無い提出」を判定している（`freshness.py::pending_filings`）。新しいワークフロー（例 `SEC_Filing_Watch.yml`、平日1〜2回）が submissions だけを取り、新しい 10-K/10-Q がある銘柄を `SEC_Data_Update` に `tickers` 付きの `workflow_dispatch`（`GITHUB_TOKEN` の `gh workflow run` は連鎖を起こせる）で渡す。連鎖は既存の workflow_run のまま（HypeCore→TANUKI）。
- **TAIL の RSS を使う案は不向き**: RSS は保有9銘柄だけで、`edgar_rss_monitor.py` は TAIL の提出の検知（本文の取り込み用）。82銘柄に広げるより、submissions（鮮度の確認で既に使っている）に寄せるほうが道具が1つで済む。
- **回数・負荷**: 検知は82銘柄で82リクエスト（SEC の上限10回/秒の十分内、約20秒）×平日1〜2回。取得は提出のあった銘柄だけ（決算期は1日に5〜10銘柄、company_facts は1銘柄約2.7MB）。実行は 検知（数分）＋`SEC_Data_Update`（銘柄が少なければ数分）＋連鎖（HypeCore 2・EPS 3・Stonks 4・TANUKI 13分）。ただし**連鎖は全銘柄を再計算する**（TANUKI 13分）。提出が多い決算期（2月・5月・8月・11月の各3週間ほど）だけ連鎖が回り、ほかの月はほぼ回らない（実回数は未試算）。bot の commit は連鎖1回ごとに数本増える。
- **System Health・鮮度の扱い**: `_freshness.json` は `write(entries, full_run)` が部分実行を区別するので、日曜の全銘柄の実行が `generated_at` を更新する仕組みは保てる（[M] の8日の上限は日曜の実行で足りる）。平日の部分実行を足すと、[M]・CHECK-60 が部分の結果で鮮度を誤読しないかを実装の前に確かめる必要がある。日曜の全銘柄の実行は安全網として残す。
- **提出の直後は company_facts API に入っていないことがある**（CEG が13日）。検知した提出が company_facts に無い間は、毎平日取り直す（`SEC_LAG` のまま）か、翌日に再度試す。これは今の日曜でも同じ。
- **見込み**: 提出 → TANUKI は中央値 4.5日 → 約1日（提出が米国の夕方〜夜なら、検知の時刻しだい。平日の 23:30 UTC＝翌 08:30 JST に検知して翌朝の連鎖なら、提出から約1営業日）。

**決めてほしいこと**: (a) 案Aを実装するか。(b) 実装するなら検知の時刻（1日1回〈提出の翌朝〉か、2回〈米国の夕方の直後と翌朝〉か）。(c) 連鎖は全銘柄でよいか（TANUKI 13分×回数。銘柄を絞る改造は計算方法の変更の手順に関わるので別件）。(d) 部分実行の鮮度の扱い（System Health）を実装の STEP 0 で先に確かめるか。

### 案B: 間に合わない間の表示（取り込み前の印）

- 条件: 決算の発表日（今日以前）があり、その銘柄の Layer3 の最新の提出日がその発表日より前（`_freshness.json` の `local_latest_filed` < 発表日 ≤ 今日）。印は「最新の決算は反映前（決算 11-18・取り込み済みは 08-26 まで）」。TANUKI SCORE・銘柄の詳細・HypeCore・STONKS の画面で同じ表示を使う。
- **決算の発表日の取得元（今あるもの）**: (1) `common/market_data/attributes/{T}.json` の `calendar.earnings_date`（yfinance。Market Data Weekly〈日曜〉が更新、日々の更新は無い）、(2) TANUKI の `latest.json` の `next_earnings_date`（(1)を読む）。どちらも**予定日**で、過ぎた日がしばらく残るか次の四半期に進むかはYahooしだい（例: NVDA は 11-22 の取得で 11-18 のまま）。誤差・取り消しがある。
- **より確かな取得元（追加の費用0）**: 案Aの submissions に 8-K の提出が出る。`items` に `2.02`（決算の結果）が付いた 8-K の提出日＝実際の決算の発表日。鮮度の確認で既に取っている応答の別の欄を読むだけで、リクエストは増えない。
- 印だけなら計算方法の変更ではない（表示だけ。理論株価・判定は変えない）。案Aとは独立に入れられ、案Aを入れた後も「発表→取り込みの間」の印として残る。

**決めてほしいこと**: (e) 印を入れるか（案Aなしでも入れられる）。(f) 発表日を Yahoo の予定日で足りるとするか、8-K の 2.02 にするか（後者は検知の実装が要る）。(g) 表示の場所。

### 8-K の決算資料の数字

使わない前提でよい。決算の発表資料（Exhibit 99.1）は HTML・PDF で XBRL ではなく、項目名・単位・期間が会社ごとに違い、Layer3 の定義（タグ・TTM）に合わせられない。10-Q の XBRL（company_facts）とも別の基準（調整後の数字・ガイダンスを含む）になる。使える場合があるとすれば、(1) 発表の日付（上の 2.02 の提出日）、(2) 10-Q の提出が遅れる銘柄（NVDA のように発表と提出が離れる）の暫定の確認（表示のみ・計算には入れない）、の2つだけ。

## 4. 間に合わせる必要があるかの判断材料

遅れで判定が変わった例（TANUKI の `latest.json` の `tanuki_score` を、新しい期末が入った commit とその直前の commit で比べた）: 62銘柄中、判定が変わったのは11銘柄。うち5銘柄は計算方法の変更（`method_change`: CDNS・GOOGL・MSFT＝QUARTERLY-BASIS-MIX-1、HON・TSLA＝LAYER3-FIRST-FILED-DATE-1）が同じ回に入っていて除く。**計算方法の変更が無い6銘柄**:

| 銘柄 | 提出 → TANUKI | 判定の変化 | 理論株価 |
|---|---|---|---|
| CAKE | 11-02 提出 → 11-09 | HOLD → TRIM | 41.5 → 38.8 |
| CELH（保有） | 11-05 → 11-09 | HOLD → WATCH | 28.1 → 33.4 |
| CIX | 11-04 → 11-09 | TRIM → HOLD | 26.5 → 27.8 |
| DOCN | 11-03 → 11-09 | TRIM → HOLD | 33.9 → 65.0 |
| V | 11-05 → 11-09 | TRIM → HOLD | 292.5 → 326.9 |
| ZETA | 11-09 → 11-16 | HOLD → WATCH | 34.7 → 40.9 |

- 注意: 判定は funda に加えて timing（株価）も入る。1週間の株価の動きが混ざる。funda の点が動いたのは CIX（80→65）・DOCN（65→50）・ZETA（90→100）。CAKE・CELH は timing（株価）の動きが主、V は funda・timing とも同じで理論株価の変化（292→327、上昇余地の変化）による。**遅れだけが原因の判定の変化とは言えない**。
- 理論株価が1回で10%超動いた銘柄は 62 中 30（DOCN 33.9→65.0、PAYS 28.4→74.9、FICO 917→1357、SITM 98.9→15.3 など。計算方法の変更も混ざる）。決算の直後の判断が前の四半期の値で見えるのは、約1週間。
- 保有（TAIL の9銘柄）で判定が変わったのは CELH だけ。TSLA の変化は計算方法の変更が同じ回。
- **判断の材料**: 週に1回でも判定が実際に変わった例はある（6銘柄・約10%）。一方で、変化は timing（株価）にも依り、遅れだけの影響ではない。買いの判断（11-22 の NVDA のような）に使うなら、約1営業日の反映が欲しい。表示（案B）だけなら安い。
