# EPS-REVISION-OUTLOOK-MARK-1 STEP 0（2026-11-28、読み取りだけの調査。コード・データは変えていない）

依頼: EPS 予想の改定（上方・下方）を、見通しの悪化の印として個別銘柄の画面と BUY チェックリストに出す件の、材料の確認。
**限界（先に）**: yfinance の読み取りだけ（2026-11-28 の1回の取得）。**過去の時点の予想の保存は無い**ので、「下落の前に印が出ていたか」は、`eps_trend` が持つ4つの過去の点（7・30・60・90日前）と日足の終値の並べでしか見られない（先行する印か、遅れて追う印かの検定ではない）。

読み取り（**4銘柄の並べで、検定ではない**）:
- **下落の前に印が出ていたとは言えない。印は下落の後に追って出ている**。
  - **NOW**: 10-29 の −26.9% の前、予想 EPS は 90日前〜30日前で動いていない（4.07 のまま）。予想 EPS が下がったのは 10-29 から 11-21 の間（下落の後の3週間以内）。下方の改定の件数（0y で下げ35件）は 30日と7日で同じ（＝直近7日に集中）と返るが、`eps_trend` では 7日前の時点で既に下がっていて、**yfinance の2つの項目の時点が合わない**（件数の数え方の確認が STEP 1 で要る）。
  - **INTU**: 11-20 の −12.8% の前の弱い兆しは、`0q` が 90日前〜30日前で −7.7%（4.17 → 3.85）、`0y` が −4.4%。大きな下げ（`0q` 7日前比 −14.8%、下げ19件）は**下落の後**（11-21 以降）。
  - **CRM**: 価格は 256 → 181 と下がったが、予想 EPS は**上がっている**（+0.5〜+2.2%）。見通しの下方の印は出ない。

- つまり印は、**「見通しが悪化した後も、予想がまだ下がり続けている」ことの確認（遅れて追う）**には向くが、**11-22 の買いの検討で見落とした「先行する悪化」には出ない**（INTU・NOW は追って出る、CRM・NVDA は出ない）。表示の目的を「確認」と書くのが正直。
- 検定には、**過去の時点の保存が要る**。`eps_trend` の4つの過去の点は1回の取得で90日ぶんを返すが、毎週の保存が無いと、後から先行性を測れない。

## 3. 今の表示・TANUKI-GUIDANCE-REVISION-BLIND-1・BUY チェックリストとの関係

- **GUIDANCE（成長率−アナリスト予想の差）**（`common/guidance_gap.py`、2026-11-25 公開）: TANUKI の成長率 − アナリストの**売上**予想の伸び（次の会計年度）を `growth_gap_pt` に、その**同じ期間 `+1y` の EPS 予想の改定の件数（30日）**を `revisions_up_30d`・`revisions_down_30d` に出す。TANUKI SCORE の列「成長率−予想(pt)」（`tanuki_score/index.html`）と、個別銘柄の画面（`stock.html` の「成長率の前提とアナリストの予想の差」）が読む。**EPS の改定は `+1y` の件数のみで、幅も `0q`・`0y` も出ていない**。INTU の悪化は `0q`（当四半期）に出る（上の表）ので、今の表示では見えない。
- **TANUKI-GUIDANCE-REVISION-BLIND-1**（案1 公開済み）: 「見通しが下がっても理論株価に出ない」への対応の第1段で、**表示だけ**にとどめた（成長率に入れる案は、決定(c)・FCF-OUTLIER-QUAL-1 の原則と合わず勧めていない）。EPS-REVISION-OUTLOOK-MARK-1 は、その表示を **期間（0q・0y・+1y）と幅（`eps_trend`）に広げる**位置づけ。
- **BUY チェックリスト**は **Market Pulse の市場全体の判定**（CNN F&G ≤ 25 で発動し、S&P500 の200日線・HY スプレッド・ヒンデンブルグの3つの確認で BUY／WATCH）。**個別銘柄の項は無い**。「BUY チェックリストに出す」を、次のどちらにするかを決める必要がある（§5）。

### 整合する出し方（案）
1. **個別銘柄**（推奨）: `stock.html` の「成長率の前提とアナリストの予想の差」のブロックの下に、同じ書式の「**EPS 予想の改定**」の行を足す（0q・0y・+1y の、30日の上げ・下げと、90日前比。印は B・D のどちらかの規則）。TANUKI SCORE の列は、GUIDANCE の列の隣に**1列**（印の有無と、悪化した期間）。
2. **BUY チェックリスト**: 市場全体の判定なので、個別の改定は入れない。整合する形は、**市場の判定の「参考」として「監視銘柄のうち予想 EPS の改定が悪化の印に当たる割合」を出す**（4つ目の確認ではなく参考。判定は変えない）か、**出さない**かのどちらか。個別の BUY（TANUKI SCORE の決定）を印で下げる案は、判定に入れることになるので、今は勧めない（表示だけの原則）。

## 4. 保存を増やしたときの容量

実測（`attributes/{T}.json` は589ファイルで計706KB、平均1,227バイト。うち `estimates` の欄は平均349バイト〔83銘柄〕）。

| 案 | 1銘柄あたりの増え方 | 82銘柄 | git の履歴 |
|---|---|---|---|
| **今の保存を広げる**: `eps_revisions` を4期間・4項目に、`eps_trend` を4期間×5点で保存（`attributes/{T}.json` の `estimates` に、毎週上書き） | `estimates` が約 188 → 約 801 バイト（**+約 613 バイト**） | **約 50KB**（`attributes/` の約 7%） | 毎週の差分が約 50KB → **約 2.6MB/年** |
| **週1の履歴を足す**（追記だけ。`valuation_history` と同じ形。1行〔日付＋4期間の件数4つ＋`eps_trend` 5点〕を圧縮した配列で約 194 バイト） | 約 194 バイト/週 | 約 16KB/週 | **約 0.8MB/年**（過去の時点の保存で、先行性の検定ができる） |

- **`market_data.json`（Market Pulse、5.0MB）には入れない**（銘柄ごとの値ではないため）。「監視銘柄のうち悪化の割合」を市場の参考に出す案でも、数値1〜2個で増えは無視できる。
- 取得は**今の週1回（Market Data Weekly）の `estimates` の取得に乗る**（追加の API の呼び出しは無い。`eps_trend` は同じ `Ticker` から取れる。今日の82銘柄の取得は6並列で約2秒）。

## 5. 決めてほしいこと

2. 規則: B（当四半期の予想 EPS が30日前比 −5% 以下）か D（正味 −3件以下かつ 30日前比 −2% 以下）か、両方か。
